# 我的世界服务器配置：从选机型到改 server.properties，一份能直接照抄的开服清单

搜「我的世界服务器配置」的人，基本是两种状态。

一种是还没买机器，正卡在预算和参数之间：2核4G 到底能带几个人？1.20 是不是必须上高主频？带宽 10M 和 20M 差在哪？另一种是机器已经在手上了，打开 `server.properties` 看到一长串英文，知道该动，但不知道动哪个。

这两种状态其实是同一件事的两端：硬件配置决定你的上限，服务端配置决定你能摸到上限的几分之几。下面就把这两端拆开讲，中间顺带把落地的机器方案说清楚。

## MC 服务器真正吃的是什么

先说一条会省你很多钱的结论：Minecraft 主要吃**单核性能**。

区块加载、实体运算、红石、插件事件调度，绝大部分逻辑跑在主线程上。你给它 8 核，主线程还是只用一个核。多出来的核心主要用来分担 GC、异步区块生成和别的服务端进程。所以看配置时先看单核强不强，再看核数够不够用——雨云的游戏云选购页干脆直接用 CPU-Z 单核跑分给机型划性能区间，就是这个道理。

排在单核后面的是内存，而且版本越新越夸张。雨云官方页面写得很直白：**1.18+ 的消耗约为 1.16+ 的两倍，是 1.12.2 的三倍**。也就是说，一台在 1.12.2 时代还算宽裕的 2核2G，直接搬去开 1.20，玩家进图就会开始体验什么叫"走一步退两步"。

## 机器到手之后：真正需要动的配置项

装好服务端，`server.properties` 里值得动的其实不到十个。剩下的保持默认更安全。

| 配置项 | 建议值 | 为什么 |
| --- | --- | --- |
| `view-distance` | 6–8，人多就往 6 压 | 性能影响最大的单项，和玩家数、内存直接挂钩 |
| `simulation-distance` | 4–6 | 决定实体和红石的活跃半径，比视距更吃 CPU |
| `max-players` | 按实际人数设 | 设大了没意义，设小了会拒人 |
| `online-mode` | 有正版账号就保持 `true`，纯私服可改 `false` | 关掉验证等于谁都能进，外网开服慎改 |
| `spawn-protection` | 私服可以设 0 | 不然离出生点近的建筑改不了 |
| `difficulty`、`pvp` | 按玩法 | 纯口味问题，不影响性能 |

JVM 参数比这些更容易被忽略。官方原版启动脚本给的内存常常偏小，实际建议把 `-Xms` 和 `-Xmx` 设成同一个值，避免运行中反复扩容；GC 用 G1 更稳，常见写法是 `-XX:+UseG1GC -XX:MaxGCPauseMillis=50`。4G 内存的机器，JVM 一般给 3G 左右就够了——把内存全塞进 JVM，操作系统自己没得用，反而容易出问题。

还有两件容易被跳过的事：一是**端口映射**。NAT 机型没有独立公网 IP，需要把 25565 映射出去（MCSM 面板本身要 23333 和 24444），面板上生成的外部端口就是玩家要填的地址。二是**备份**。MCSM 面板支持文件管理直接下载 world 文件夹，定时下一下，比出事之后找恢复手段便宜得多。

## 计费方式选错，比配置买贵更亏

雨云游戏云有两种计费：固定计费和动态计费。

固定计费就是月租，跑不跑都这个价。动态计费基础费用低，但按 CPU 实际使用量结算电量费——闲置下来几乎不花钱，忙起来会叠加。第三方整理的单价是：Ryzen 5900X 机型 0.0008 元/电量，7950X / 9950X / 13900K / 14900K 机型 0.001 元/电量。

判断标准很简单：**和朋友固定每天晚上开两小时以上，用固定计费；碎片时间想起来才玩，用动态计费**。长期 24 小时挂着的服选动态计费，最后账单大概率比固定月租还难看。

## 几个被问得最多的问题

**2核4G 真能带十几个人？**
官方参考是纯净服 12+ 人，前提是视距压在 6 左右、不加重型插件。你再加个视距 12 和一堆实时计算型插件，数字就不成立了。

**为什么没人上线服务器也占资源？**
区块加载、实体、刷怪、红石都在跑。真正的差别在于动态计费按 CPU 用量算钱，而性能问题需要靠降低 `simulation-distance` 和清理实体类插件解决。

**该选哪个 CPU？**
雨云在售机型从 E5 2666V3、Platinum 8275cl、Gold 6146，到 Ryzen 5900X、7950X、9950X 和 i9 14900K。开 1.18+ 的中大型服，优先考虑 5900X 及以上；低版本小型纯净服或挂机服，低配机型够用还便宜。

**NAT 够用吗，要不要买独立 IP？**
NAT 模式多人共用一个公网 IP，但可以映射 15 个端口，开私服足够。需要固定地址、要挂网站或对防护有单独要求，再考虑加购独立 IP。

**卡顿先调哪里？**
顺序是：视距 → 模拟距离 → 实体清理/优化插件 → 内存分配 → 最后才考虑升配。前三步不花钱。

## 一份可以直接抄的开服清单

1. 先估人数和玩法，再选内存和核心数，别反过来。
2. 单核性能优先，尤其 1.18 以上版本。
3. 1.20+ 别指望老低配机器，官方数据里它的消耗是 1.12.2 的三倍。
4. 视距先设 6–8，觉得没问题再往上试。
5. JVM 的 `-Xms` 和 `-Xmx` 设成同值，留出系统内存。
6. 端口该映射的全映射：MC 一个，面板自己两个。
7. 计费方式按"每天玩多久"选，不是按价格高低选。
8. 存档手动备份，别等出事才想起来。

配置这件事没有标准答案，但有一条判断永远成立：花在单核和内存上的钱，比花在核数和带宽上的钱更值。
